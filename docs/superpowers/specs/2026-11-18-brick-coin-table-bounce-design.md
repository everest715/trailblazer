# 砖块金币桌边反弹设计

## 目标

砖块生成的金币沿现有抛物线飞行时，如果碰到当前桌面的边缘，应在接触点反射回桌内，而不是飞出桌面。真实桌面、统一虚拟桌面和固定区域回退使用同一套行为。

## 非目标与约束

- 保留现有飞行距离、弧线高度、持续时间、金币收集和碰撞体恢复逻辑。
- 不新增物理围墙，不给金币添加 Rigidbody，不修改第三方模型或 Prefab。
- 不改变敌人和道具的桌面约束，不处理金币落地后的滚动。
- 没有桌面区域的独立 `CollisionEffect` 继续使用原有直线抛物线。
- Editor 测试由用户手动运行；真机外观仍需 PICO 验证。

## 方案比较

### 采用：基于桌面多边形的轨迹反射

生成器已经把本次使用的 `PicoFloorArea` 传给生成事件。让生成器同时把该区域配置到砖块的 `CollisionEffect`，再把区域传给 `CoinArcFlight`。飞行路径在 XZ 平面求最近边交点，反射水平方向后继续剩余距离，垂直弧线仍按总进度计算。

优点是确定性强、可直接测试，并且真实桌面和虚拟桌面共用同一区域来源，不需要物理围墙。

### 不采用：物理碰撞反弹

为桌边增加碰撞体并给金币添加 Rigidbody，会改变现有运动与收集碰撞，且还需要新增和维护真实桌面的围墙物理几何，不符合本次最小改动目标。

## 实现分工

- `PicoSceneSpawnPositions.SpawnAt`：在触发生成事件前，将本次实际使用的区域配置给实例上的 `CollisionEffect`。场景识别和固定区域回退都经过此入口。
- `CollisionEffect`：保存可选桌面区域，并在创建金币时传给 `CoinArcFlight.Launch`；没有区域时维持旧行为。
- `CoinArcFlight`：有区域时把水平路径拆成若干线段，选择最近有效边交点并反射方向，支持连续反弹；保留原有总距离、垂直弧线和落地恢复逻辑。退化边、零方向和浮点边界不得产生 NaN 或死循环。

## 验证

- 金币从方形区域中心向边外发射：到达边缘后折返，最终落点在桌内，落地后原碰撞体状态恢复。
- 区域不交叉的直线飞行保持原落点；无区域飞行保持原行为。
- 生成器生成的 `CollisionEffect` 收到与 `SpawnedInArea` 相同的区域，固定区域回退同样成立。
- 用户手动运行相关 PlayMode 测试和完整回归；随后在 PICO 上验证真实桌面、虚拟桌面及桌边收集。
